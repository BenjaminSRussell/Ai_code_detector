=============================================================================
WHAT CANNOT BE DONE
=============================================================================

Definitive Proof:
  - Cannot prove code is AI-generated with certainty
  - Provides probabilistic estimates only
  - Should not be sole evidence for decisions

Language Support:
  - Full AST analysis only for Python
  - Other languages use limited regex analysis
  - Cannot parse complex language-specific constructs

Adversarial Resistance:
  - Can be fooled by manual editing
  - Variable renaming reduces detection
  - Comment removal lowers scores
  - Not designed for adversarial evasion

Model Specificity:
  - Cannot distinguish between different AI models
  - Cannot identify specific AI assistant used
  - Works on general AI patterns only

Real-time Detection:
  - Not designed for IDE integration
  - Not fast enough for pre-commit hooks
  - Best for batch repository analysis

=============================================================================
KNOWN ISSUES AND LIMITATIONS
=============================================================================

1. Language Support:
   - Full analysis only for Python
   - Other languages have limited structural analysis
   - Tree-sitter integration needed for full multi-language support

2. False Positives:
   - Well-documented human code may score high
   - Consistent formatting triggers detection
   - Generic naming in legitimate code flagged

3. False Negatives:
   - Heavily edited AI code may score low
   - Domain-specific AI code less detectable
   - Mixed human-AI collaboration hard to detect

4. Performance:
   - Not optimized for very large repositories (>10K files)
   - Git history analysis can be slow on old repos
   - No incremental analysis (full re-scan required)

5. Dependencies:
   - Requires GitPython (cannot analyze non-git directories fully)
   - MLX features only work on Apple Silicon
   - Qwen features require large model downloads
